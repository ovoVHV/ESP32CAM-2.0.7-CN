# ESP32-CAM 人脸识别与云端上传系统操作手册

| 项目 | 内容 |
| --- | --- |
| 文档名称 | ESP32-CAM 人脸识别与云端上传系统操作手册 |
| 对应工程 | `ESP32CAM_JPEG_CN` |
| 适用对象 | 毕业设计验收教师、系统演示人员、普通使用者 |
| 硬件平台 | AI Thinker ESP32-CAM |
| 软件核心 | Arduino-ESP32 core 2.0.7 |
| 主要功能 | 摄像头预览、人脸录入、人脸识别、图片上传、状态上报 |

## 1. 系统简介

本系统基于 ESP32-CAM 开发板实现人脸识别与云端消息上传功能。系统上电后连接 WiFi，并启动本地网页服务。用户通过浏览器访问 ESP32-CAM 的 IP 地址，可以查看摄像头实时画面、录入人脸、删除人脸数据。系统检测到人脸后会自动进行识别，并将当前图像上传到巴法云图片主题，同时将识别结果发送到巴法云状态主题。

当前版本不包含继电器、蜂鸣器、红绿灯等外接门禁硬件控制，主要用于毕业设计中的人脸识别、图像采集、云端上传和状态通知演示。

## 2. 系统功能

系统具备以下功能：

| 功能 | 说明 |
| --- | --- |
| WiFi 连接 | ESP32-CAM 开机后自动连接指定 WiFi |
| 网页预览 | 浏览器访问设备 IP 后显示摄像头画面 |
| 人脸录入 | 输入姓名后采集多次人脸样本并保存 |
| 人脸识别 | 系统默认进入自动识别状态 |
| 人脸删除 | 支持删除单个人脸和全部人脸 |
| 图片上传 | 检测到人脸后上传 JPEG 图片到巴法云 |
| 状态上报 | 将识别成功或识别失败的文字消息发送到巴法云 |
| Flash 保存 | 通过 `fr` 分区保存人脸样本，正常情况下重启不丢失 |

## 4. 硬件准备

### 4.1 必需硬件

| 硬件 | 数量 | 说明 |
| --- | ---: | --- |
| AI Thinker ESP32-CAM | 1 | 主控与摄像头模块 |
| OV2640 摄像头 | 1 | 建议使用支持 JPEG 的摄像头 |
| USB 转 TTL 下载器 | 1 | 用于烧录程序 |
| 杜邦线 | 若干 | 用于连接下载器和 ESP32-CAM |
| 5V 电源 | 1 | 建议电流能力不低于 1A |
| 电脑或手机 | 1 | 用于访问网页和查看演示效果 |

### 4.2 烧录接线

常见 USB 转 TTL 与 ESP32-CAM 接线如下：

| USB 转 TTL | ESP32-CAM |
| --- | --- |
| 5V | 5V |
| GND | GND |
| TX | U0R |
| RX | U0T |
| GND | IO0 |

注意：

```text
烧录程序时，IO0 需要接 GND。
烧录完成后，断开 IO0 与 GND，再重新上电运行程序。
```

如果串口一直没有正常启动信息，优先检查 IO0 是否已经断开。

## 6. 程序配置

打开主程序：

```text
ESP32CAM_JPEG_CN.ino
```

### 6.1 WiFi 配置

找到以下代码：

```cpp
const char *ssid = "YOUR_WIFI_SSID";
const char *password = "YOUR_WIFI_PASSWORD";
```

将其修改为实际 WiFi 名称和密码。

要求：

- ESP32-CAM 和浏览器设备必须在同一个局域网内。
- WiFi 信号要稳定。
- 建议使用 2.4GHz WiFi。

### 6.2 巴法云配置

代码中包含以下配置项：

```cpp
const char *BEMFA_UID = "YOUR_BEMFA_PRIVATE_KEY";
const char *BEMFA_TOPIC = "stu";
const char *BEMFA_STATUS_TOPIC = "status";
```

含义：

| 配置项 | 作用 |
| --- | --- |
| `BEMFA_UID` | 巴法云私钥 |
| `BEMFA_TOPIC` | 图片上传主题，当前为 `stu` |
| `BEMFA_STATUS_TOPIC` | 状态消息主题，当前为 `status` |

注意：

```text
BEMFA_UID 是私密信息，不建议写入公开论文附件或开源仓库。
如果需要提交代码，可以用占位符代替真实私钥。
```

### 6.3 人脸库容量配置

代码默认配置：

```cpp
#define ENROLL_CONFIRM_TIMES 5
#define PERSON_SAVE_NUMBER 7
```

含义：

- 每个人录入 5 次样本。
- 最多保存 7 个人。
- 总样本数量约为 35 个。

毕业设计演示时，建议录入 1 到 3 个人即可，便于控制演示效果。

## 7. 编译与上传

### 7.1 打开工程

使用 Arduino IDE 打开：

```text
ESP32CAM_JPEG_CN\ESP32CAM_JPEG_CN.ino
```

### 7.2 选择开发板

在 Arduino IDE 中选择：

```text
Tools -> Board -> esp32 -> AI Thinker ESP32-CAM
```

建议配置：

| 选项 | 建议 |
| --- | --- |
| Board | AI Thinker ESP32-CAM |
| Upload Speed | 115200 或 921600 |
| CPU Frequency | 240MHz |
| Flash Frequency | 80MHz |
| Flash Mode | QIO 或 DIO |
| Partition Scheme | 使用工程内 `partitions.csv` |
| PSRAM | Enabled |

如果编译或上传异常，可以先将 Upload Speed 调低到 `115200`。

### 7.3 上传程序

1. 将 ESP32-CAM 的 `IO0` 接 `GND`。
2. 点击 Arduino IDE 的上传按钮。
3. 等待上传完成。
4. 断开 `IO0` 与 `GND`。
5. 按下复位键或重新上电。

### 7.4 打开串口监视器

设置波特率：

```text
115200
```

正常启动时，串口会输出类似信息：

```text
WiFi 已连接
网页服务已启动
Flash 模式：已载入 0 个人脸样本
摄像头已就绪，请打开 http://192.168.xxx.xxx/
```

记录该 IP 地址，后续浏览器访问需要使用。

## 8. 网页访问

在电脑或手机浏览器中输入串口显示的地址，例如：

```text
http://<DEVICE_IP>/
```

打开后可看到：

- 摄像头实时画面。
- 当前状态提示。
- 姓名输入框。
- `录入人脸` 按钮。
- 已录入人脸列表。
- `全部删除` 按钮。

网页显示 `已连接` 后，表示浏览器已经与 ESP32-CAM 建立 WebSocket 通信。

## 9. 人脸录入操作

### 9.1 录入前准备

录入时建议：

- 人脸正对摄像头。
- 光线充足，不要逆光。
- 人脸位于画面中央。
- 距离摄像头约 30cm 到 80cm。
- 保持头部稳定。

### 9.2 录入步骤

1. 在网页输入框中输入姓名，例如 `张三`。
2. 点击 `录入人脸`。
3. 保持人脸对准摄像头。
4. 系统会连续采集 5 次样本。
5. 网页会显示类似信息：

```text
正在录入 张三：第 1/5 次
正在录入 张三：第 2/5 次
正在录入 张三：第 3/5 次
正在录入 张三：第 4/5 次
正在录入 张三：第 5/5 次
张三 录入完成
```

录入完成后，姓名会出现在 `已录入人脸` 列表中。

### 9.3 录入建议

为了提高识别率，5 次录入可以轻微变化角度：

| 样本 | 建议姿态 |
| --- | --- |
| 第 1 次 | 正脸 |
| 第 2 次 | 稍微靠近 |
| 第 3 次 | 稍微远离 |
| 第 4 次 | 轻微左偏 |
| 第 5 次 | 轻微右偏 |

不要变化过大，否则系统可能认为不是同一张脸。

## 10. 人脸识别操作

当前版本默认进入自动识别状态。网页连接后，不需要点击额外的“识别”按钮。

识别流程如下：

```text
摄像头采集画面
-> 系统检测是否有人脸
-> 检测到人脸后与已录入样本比对
-> 输出识别结果
-> 上传图片到巴法云
-> 发送状态到巴法云
```

### 10.1 识别成功

当识别到已录入人员时，网页显示：

```text
识别成功：姓名
```

串口可能显示：

```text
识别成功：姓名
Bemfa upload OK, HTTP 200
Bemfa status OK, HTTP 200, msg: 主人识别成功
```

同时：

- 当前图片上传到巴法云 `stu` 主题。
- 状态消息 `主人识别成功` 发送到 `status` 主题。

### 10.2 识别失败

当检测到人脸但没有匹配到已录入人员时，网页显示：

```text
未识别到已录入人脸
```

串口可能显示：

```text
未识别到已录入人脸
Bemfa status OK, HTTP 200, msg: 不是主人在人脸识别
```

同时：

- 当前图片上传到巴法云 `stu` 主题。
- 状态消息 `不是主人在人脸识别` 发送到 `status` 主题。

### 10.3 云端上报间隔

系统默认设置：

```cpp
CLOUD_REPORT_COOLDOWN_MS = 30000;
```

表示 30 秒内最多上报一次图片和状态。

这样可以避免：

- 持续有人站在摄像头前导致重复上传。
- ESP32-CAM 因频繁上传而卡顿。
- 巴法云主题消息过多。

## 11. 人脸删除操作

### 11.1 删除单个人脸

在 `已录入人脸` 列表中，每个人名后有 `删` 按钮。

点击后，系统会删除该姓名对应的人脸样本。

### 11.2 删除全部人脸

点击网页中的 `全部删除` 按钮。

执行后：

- 网页人脸列表清空。
- ESP32-CAM 内部人脸库清空。
- 如果 `fr` 分区正常，Flash 中保存的人脸也会清空。

删除后如需继续识别，需要重新录入人脸。

## 12. 巴法云查看方式

### 12.1 图片主题

当前图片主题：

```text
stu
```

检测到人脸并触发上报后，可以在巴法云平台查看上传图片。

### 12.2 状态主题

当前状态主题：

```text
status
```

可能收到的消息：

```text
主人识别成功
不是主人在人脸识别
检测到人脸但没有录入主人
检测到人脸
```

如果 `status` 是 MQTT 主题，代码中的：

```cpp
"type": 1
```

保持不变。

如果 `status` 是 TCP 主题，需要将 `type` 改为 `3`。

## 13. 正常演示流程

毕业设计答辩或演示时，建议按以下流程操作：

1. 给 ESP32-CAM 上电。
2. 打开串口监视器，确认 WiFi 连接成功。
3. 记录串口输出的 IP 地址。
4. 浏览器访问该 IP 地址。
5. 确认网页能显示摄像头画面。
6. 输入姓名并录入人脸。
7. 录入完成后，让已录入人员面对摄像头。
8. 观察网页是否显示 `识别成功：姓名`。
9. 打开巴法云平台，查看图片主题是否收到图片。
10. 查看 `status` 主题是否收到 `主人识别成功`。
11. 更换未录入人员面对摄像头。
12. 观察网页是否显示未识别。
13. 查看 `status` 主题是否收到 `不是主人在人脸识别`。
14. 演示删除人脸或全部删除功能。

## 15. 常见问题与处理

### 15.1 编译失败：找不到 `camera_index.h`

现象：

```text
fatal error: camera_index.h: No such file or directory
```

原因：

```text
主程序所在目录缺少 camera_index.h。
```

处理：

- 确认 `camera_index.h` 与 `.ino` 文件在同一工程目录。
- 不要只复制 `.ino`，需要复制整个 `ESP32CAM_JPEG_CN` 文件夹。

### 15.2 网页打不开

可能原因：

- ESP32-CAM 未连接 WiFi。
- 电脑或手机与 ESP32-CAM 不在同一网络。
- IP 地址输入错误。
- ESP32-CAM 供电不足。

处理：

- 查看串口输出的 IP 地址。
- 确认浏览器访问的是 `http://设备IP/`。
- 换用 5V 稳定电源。
- 重新上电。

### 15.3 摄像头初始化失败

现象：

```text
摄像头初始化失败，错误码 0x...
```

可能原因：

- 摄像头排线松动。
- 摄像头型号不匹配。
- 开发板不是 AI Thinker 引脚定义。
- 供电不足。

处理：

- 重新插拔摄像头排线。
- 确认使用 OV2640 摄像头。
- 确认代码中启用 `CAMERA_MODEL_AI_THINKER`。
- 使用稳定 5V 电源。

### 15.4 录入后重启丢失

可能原因：

```text
fr 分区没有正确写入。
```

串口可能出现：

```text
未找到人脸分区 fr
```

处理：

- 确认工程目录中有 `partitions.csv`。
- 重新编译并上传。
- 清除 Flash 后重新上传。

### 15.5 检测不到人脸

可能原因：

- 距离太近或太远。
- 光线不足。
- 人脸不在画面中央。
- 摄像头画面过暗或过曝。

处理：

- 调整距离到 30cm 到 80cm。
- 保持正脸。
- 增加环境光。
- 避免强逆光。

### 15.6 识别很卡

原因：

```text
ESP32-CAM 算力有限，人脸检测和识别会占用较多 CPU。
```

当前代码已经通过以下方式降低卡顿：

```cpp
RECOGNIZE_INTERVAL_MS = 3000;
PREVIEW_INTERVAL_MS = 100;
CLOUD_REPORT_COOLDOWN_MS = 30000;
```

如果仍然很卡，可以适当增大：

```cpp
RECOGNIZE_INTERVAL_MS
```

例如从 `3000` 改为 `4000` 或 `5000`。

### 15.7 巴法云图片上传出现 HTTP -11

现象：

```text
Bemfa upload failed, HTTP -11
```

原因：

```text
通常是 HTTPClient 等待图片接口响应超时。
```

处理：

- 确认 WiFi 稳定。
- 减少频繁识别和上传。
- 保持图片分辨率为 QVGA。
- 如果状态主题能收到消息，说明主流程仍然正常。

### 15.8 状态主题没有消息

检查：

- `BEMFA_UID` 是否正确。
- `BEMFA_STATUS_TOPIC` 是否为 `status`。
- 巴法云主题类型是否为 MQTT。
- 如果是 TCP 主题，需要把 JSON 中的 `type` 从 `1` 改为 `3`。

## 16. 维护说明

### 16.1 修改网页

如果修改了：

```text
HTML_interface.html
```

需要重新生成：

```text
camera_index.h
```

否则 ESP32-CAM 显示的网页仍然是旧版本。

### 16.2 修改 WiFi 或巴法云配置

修改 `.ino` 后，需要重新编译并上传程序。

### 16.3 清空人脸库

可以通过网页点击：

```text
全部删除
```

也可以重新烧录并清空 Flash，但毕业设计演示时推荐使用网页按钮，过程更直观。

## 17. 使用注意事项

1. 本系统适合毕业设计演示、学习和实验，不建议作为正式安全门禁系统。
2. ESP32-CAM 人脸识别没有活体检测，照片可能造成误识别。
3. 人脸识别效果受光照、角度、距离影响明显。
4. 巴法云私钥不要公开展示。
5. 烧录时 IO0 接 GND，运行时 IO0 必须断开 GND。
6. 供电不足会导致摄像头初始化失败、画面卡顿或自动重启。
7. 浏览器保持打开时，系统才会持续进行网页预览和识别处理。

## 18. 毕设答辩讲解词参考

可以这样介绍系统：

```text
本系统以 AI Thinker ESP32-CAM 为硬件平台，基于 Arduino-ESP32 core 2.0.7 开发。
系统上电后连接 WiFi，并启动本地 Web 服务。用户可以通过浏览器访问 ESP32-CAM 的 IP 地址，查看实时画面并录入人脸。
系统默认进入自动识别状态，当摄像头检测到人脸后，会将当前人脸与 Flash 中保存的人脸样本进行比对。
如果识别为已录入人员，网页显示识别成功，并将当前图片上传到巴法云图片主题，同时向状态主题发送“主人识别成功”。
如果识别失败，系统同样上传当前图片，并发送“不是主人在人脸识别”的警报状态。
通过该系统可以实现低成本嵌入式人脸识别、网页交互和云端消息通知功能。
```
